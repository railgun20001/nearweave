# 架构说明

## 目标

当前交付目标是两台 Windows 电脑之间的可用 MVP，同时确保应用协议、文件安全规则和界面状态不依赖某一种蓝牙 API。

## 分层

### 界面层

`src/` 只通过 Tauri command 发起操作，通过 `nearweave://state` 接收完整快照，通过 `nearweave://notice` 接收短提示。界面不直接访问文件系统或蓝牙。

### 应用服务层

- `commands.rs`：验证来自界面的意图，例如连接目标必须来自最新扫描结果，远端下载请求必须来自当前目录索引。
- `state.rs`：按稳定设备 ID 保存最多 8 个活动会话、独立高速链路与重连计划、附近设备、配对队列、信任记录、共享白名单、传输进度和接收中的文件。
- `identity.rs`：生成 Noise 静态身份，在 Windows 使用当前用户范围 DPAPI 保护私钥，并持久化可撤销的远端信任记录。
- `handlers.rs`：把收到的协议消息路由到文件、目录和剪贴板服务。
- `files.rs`：执行文件分块、哈希、临时文件落盘、目录索引与路径边界检查。
- `clipboard.rs`：在单独线程中访问系统剪贴板；Windows 通过 `WM_CLIPBOARDUPDATE` 事件唤醒，使用内容哈希抑制回环，不执行固定间隔轮询。
- `settings.rs`：只持久化明确允许跨启动恢复的用户偏好；共享目录授权仍不落盘。
- `installer_helper.rs`：Windows 原生 Rust GUI 辅助入口，执行白名单式安装迁移和防火墙规则操作；复用正式签名主程序，不创建终端进程。

### 协议层

`protocol.rs` 定义平台无关的消息和帧格式。RFCOMM、BLE GATT 或局域网传输都必须承载同一语义协议。

### 传输层

`transport/windows.rs` 使用 WinRT：

- `RfcommServiceProvider` 发布服务；
- `DeviceInformation` 扫描服务实例；
- `RfcommDeviceService` 获取连接端点；
- `StreamSocket` 建立认证加密的字节流；
- `DataReader/DataWriter` 读取和写入协议帧。

传输层只负责建立字节流、心跳和断线，不解析文件路径，也不决定剪贴板策略。

`transport/network.rs` 提供平台无关的同网高速通道：

- UDP `37991` 同时承载 NearWeave v1 自动发现、指定 IP 查询和 RFCOMM 会话发现；
- 使用 `if-addrs` 每 5 秒刷新所有有效 IPv4 网卡，并分别向网线、Wi-Fi 与 Windows 热点虚拟网卡发送定向广播；
- TCP 优先绑定 `37992`，冲突时使用动态端口，所有发现和握手信息均携带实际端口；
- 纯局域网使用 Noise XX、双方六位验证码和静态公钥信任；
- RFCOMM 授权高速链路使用临时密钥和 ChaCha20-Poly1305 逐帧认证；
- 应用状态统一选择发送队列，业务服务不复制文件或剪贴板协议。

## 连接生命周期

```text
启动应用
  → 初始化 DPAPI 保护的 Noise 身份
  → 默认恢复 NearWeave 连接服务，不读取上次停止状态
  → 始终扫描并发布已配对的 RFCOMM 服务
  → 首次启动由用户选择是否启用局域网；仅该操作可通过 GUI helper 请求 UAC
  → 已启用时校验防火墙规则，再按网卡发现局域网/热点设备并广播局域网端点
  → 已启用组件失败时按 1/2/5/10/30 秒重试
  → 连接方优先建立 Noise TCP，失败时回退 RFCOMM
  → 首次局域网连接由双方核对验证码并保存信任
  → 双方在统一主连接上发送 Hello
  → RFCOMM 主连接可继续协商加密 TCP 高速链路
  → 只交换共享根，点击目录时按 200 项分页请求直接子项
  → 纯局域网承载全部消息；混合模式的数据优先走局域网
  → 局域网主连接失效时按同一设备记录回退蓝牙
  → 任一读写失败后关闭 Socket 并按退避序列自动重连
```

每次连接分配一个 `generation`。旧连接的异步任务即使稍后结束，也不能清除更新连接的状态。

第一台连接自动成为界面发送目标，后续设备不会抢占选择；单设备内发送任务串行，不同设备可并行。本机剪贴板事件广播给全部活动设备，收到的远端剪贴板只写入本机且不会转发。停止连接会先禁止新任务，通过高优先级队列并行发送取消与断开消息，再清理本次任务登记的临时文件并释放蓝牙、UDP 和 TCP 监听；恢复连接只恢复服务和发现，不重连之前设备。

不对同一个文件执行蓝牙与局域网并行分块。当前逐块协议没有选择确认和重传窗口，并行会引入乱序重组和额外无线活动；局域网优先、蓝牙保底在当前阶段具有更好的吞吐、能耗和失败语义。链路切换时只重试正在发送的文件，目录任务中已经完成的文件保持完成状态。

## 文件接收

1. `FileOffer` 只接受文件名和声明大小。
2. 接收端清理文件名，在固定接收目录创建内部 `.part` 文件。
3. 每个 `FileChunk` 必须与期望偏移一致，累计大小不得超过声明值。
4. `FileComplete` 后刷新文件并比对大小、SHA-256。
5. 校验成功才把临时文件重命名为最终文件；失败立即删除本次临时文件。

## 共享目录

共享目录是逐层、只读能力：

- 本机只发布用户显式授权的共享根；目录内容在对方点击时只列出当前层。
- 每页最多 200 项，目录优先；每台设备最多缓存 64 个已打开目录分页，revision 变化时失效。
- 符号链接不进入列表，也不能作为列目录或下载目标。
- 下载请求不能包含绝对路径、根路径、前缀或父目录组件。
- 发送前重新 `canonicalize`，并验证真实路径仍以授权根目录开头。
- 对方没有重命名、写入、删除或执行能力。

## 后续平台适配

新增平台时保留 `protocol.rs`、`files.rs`、`handlers.rs` 和状态 DTO，只替换 `transport` 与必要的剪贴板实现。iOS 不应承诺通用 RFCOMM；应实现 BLE 控制通道，并优先探索经用户确认的局域网高速通道。
